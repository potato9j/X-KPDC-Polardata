# 서부 북극해 엽록소의 대표성과 위성 관측 한계

> **2026 극지데이터 경진대회 · 분석 결과 및 데이터 거버넌스 기록**  
> 2015–2023년 KPDC/ARAON 서부 북극해 하계 항차의 수직 프로파일을 이용하여 표층 Chl-a의 수주 대표성과 위성 관측가능성의 한계를 평가한 연구 프로젝트

## 1. Header & Overview

본 연구는 서부 북극해에서 표층 엽록소-a(Chl-a)가 0–100 m 수주 적산 Chl-a를 어느 범위까지 대표할 수 있는지 평가하고, 아표층 엽록소 최대층(Subsurface Chlorophyll Maximum, SCM), 항차 외부 예측성능 및 MODIS–현장 대응자료의 관측가능성을 구분하여 분석하였다.

공개 저장소의 목적은 연구결과와 분석 거버넌스의 **감사가능성(auditability)** 및 **추적가능성(traceability)**을 제공하는 데 있다. 저장소는 범용 실행 소프트웨어 배포를 목적으로 하지 않으며, 원본 실행 스크립트 모듈은 공개하지 않는다.

| 공개 범위 | 관리 방식 |
|---|---|
| 승인된 분석결과·표·그림 | 공개 가능 범위에서 게시 |
| 연구방법·분석경계·재현성 설명 | 공개 |
| 무결성·검증·거버넌스 기록 | 공개 가능한 요약본만 게시 |
| 원본 실행 스크립트와 오케스트레이션 모듈 | 비공개 저장소에서 관리 |
| 내부 검증 스냅샷·상태파일·마운트 경로 | 비공개 |
| 원자료 전체와 비공개 저장공간 링크 | 비공개 |

약 **14,263개, 18.1 GB** 규모의 원자료 전체는 공개 저장소에 포함하지 않는다. 공개 산출물은 원자료 전체를 대체하지 않으며, 이 저장소만으로 원자료부터 최종 결과까지의 완전한 재실행을 보장하지 않는다.

## 3. 🔒 Code Non-Disclosure & Security Governance

원본 실행 스크립트는 **통제된 비공개 저장소(Private Repository)**에서 관리한다. 이는 일반적인 지적재산권 보호나 아이디어 비공개를 주된 근거로 삼는 정책이 아니다. 코드 공개를 제한하는 이유는 인프라 보안, 파이프라인 무결성, 런타임 재현성 및 데이터 거버넌스의 네 가지 시스템 요구사항에 있다.

### 3.1 인프라 정보 노출에 따른 서버 보안 취약점  
**Information Disclosure Vulnerability**

원본 스크립트에는 `/mnt/data/...` 형식의 절대 마운트 경로, 단계별 작업영역, 상위 스냅샷 참조, 내부 파일명 규칙 및 입출력 배치가 포함되어 있다.

개별 경로 문자열만으로 시스템이 침해되는 것은 아니다. 그러나 다수의 경로, 파일명, 마운트 구조와 데이터 이동관계가 함께 공개되면 다음 정보가 추론될 수 있다.

- 물리적·논리적 저장영역의 배치
- 원자료, 중간산출물, 검증자료 및 백업 스냅샷의 분리구조
- 외부자료와 내부자료가 결합되는 처리 지점
- 단계별 읽기·쓰기 권한과 실행순서
- 내부 운영환경의 명명규칙과 디렉터리 토폴로지

이러한 정보는 공격자가 시스템의 구조를 사전 정찰하고 잠재적 접근지점을 식별하는 데 사용할 수 있으며, 결과적으로 **공격 표면(Attack Surface)**을 확대한다. 따라서 공개본에는 절대경로, 비공개 URL, 저장소 식별자, 내부 마운트 구조와 상태파일 위치를 포함하지 않는다.

### 3.2 오케스트레이션 및 파이프라인 무결성 훼손  
**Control Plane Integrity Issue**

원본 코드는 과학계산만 수행하는 독립 스크립트의 집합이 아니다. 각 분석단계의 개방·차단, 승인상태, 검증순서, 상위 산출물 권위 및 최종 잠금을 관리하는 프로젝트 전용 **제어면(Control Plane)**을 포함한다.

내부 오케스트레이션은 다음 통제요소를 결합한다.

- 단계별 Stage-Gate와 상태전이 제어
- 정의·임계값·분석경로에 대한 workflow lock
- 상위 패키지와 개별 산출물의 SHA-256 무결성 계보
- `V001`–`V050` 계열의 자동 검증 레코드
- 생산 코드와 독립 검증기의 이중 확인
- manifest, 파일크기, CRC 및 해시 불일치 검사
- 최종 수치·부호·반올림·주장경계의 잠금

이 제어 로직이 실행 맥락과 분리된 상태로 공개되면, 검증순서의 우회, 승인되지 않은 상태전이, 과거 스냅샷의 재사용 또는 미승인 산출물의 정상결과 오인이 발생할 수 있다. 이는 단순한 코드 오용 문제가 아니라 **분석계보와 결과 신뢰성을 훼손하는 파이프라인 무결성 문제**다.

따라서 공개 저장소에는 고수준의 처리흐름과 검증철학만 문서화하며, 실제 Stage-Gate 구현, lock 상태전이, validator 규칙 및 내부 검증 스냅샷은 비공개로 유지한다.

### 3.3 폐쇄형 런타임 종속성에 따른 계보 단절과 허위 재현성  
**Runtime Confounding & False Reproducibility**

원본 파이프라인은 범용 Python 환경만으로 동작하지 않는다. 일부 모듈은 다음 실행조건에 결합되어 있다.

- 내부 파일시스템과 단계별 상위 패키지 구조
- 승인 스냅샷과 상태관리 JSON
- 내부 전용 또는 환경 종속 모듈(예: `artifact_tool`)
- 이전 단계 산출물의 정확한 파일계보와 해시상태
- 특정 래스터·공간참조·폰트·문서생성 환경
- 승인된 설정값과 난수설정이 연결된 실행상태

소스 코드 일부만 공개하면 코드가 보인다는 형식적 투명성은 확보될 수 있으나, 동일한 입력권위와 상태파일이 없는 환경에서는 같은 결과를 재생성할 수 없다. 사용자가 임의로 경로, 스냅샷 또는 설정값을 대체하면 실행은 완료되더라도 원래 분석계보와 다른 결과가 생성될 수 있다.

본 프로젝트는 이러한 상태를 **재현성(reproducibility)**으로 표시하지 않는다. 원본 코드를 공개하지 않는 이유는 실행 실패를 숨기기 위한 것이 아니라, 불완전한 공개로 인해 발생하는 계보 단절과 허위 재현성 주장을 방지하기 위해서다.

### 3.4 데이터 거버넌스 컴플라이언스와 사전 유출 위험  
**Compliance & Pre-disclosure Governance**

현장자료, 외부 격자자료, 내부 검증기록 및 대회 제출 산출물은 접근권한, 목적 제한, 최소 공개 및 역할분리 원칙에 따라 관리한다.

주요 통제방침은 다음과 같다.

- 원자료와 공개 가능한 파생산출물을 분리
- 비공개 저장공간 주소와 접근 식별자를 공개 문서에서 제거
- 심사 종료 전 내부 검증 스냅샷과 핵심 제어 로직의 사전 유출 방지
- 공개 전 경로, 계정정보, 내부 상태값 및 불필요한 원자료 파일명 검토
- 심사·감사 목적과 일반 공개 목적을 구분한 접근권한 부여
- 공개범위를 결과 검토에 필요한 최소 수준으로 제한

이 정책은 확인되지 않은 라이선스 제한이나 특정 보안인증을 임의로 주장하기 위한 것이 아니다. 본 프로젝트에서 확인된 대용량 원자료의 비공개 보관, 내부 인프라 경로, 오케스트레이션 제어정보 및 심사 전 산출물의 노출위험을 관리하기 위한 기술적 통제다.

### Disclosure Boundary

| 자산 | 공개정책 |
|---|---|
| 프로젝트 개요·방법·승인 결과 | 공개 |
| 환경정보와 주요 라이브러리 버전 | 공개 |
| 공개용으로 정제된 표·그림·거버넌스 요약 | 선택적 공개 |
| 원본 실행 스크립트 | 비공개 |
| Stage-Gate·lock·validator 구현 | 비공개 |
| 내부 스냅샷·manifest 계보 전체 | 비공개 |
| 절대 마운트 경로·비공개 링크·인증정보 | 공개 금지 |
| 원자료 전체 | 공개 저장소 미포함 |

## 4. 🛠️ Code Access Policy for Reviewers

공식 심사위원 또는 권한이 확인된 평가자가 코드 검토를 필요로 하는 경우, 공개 저장소에 원본 코드를 상시 노출하지 않고 다음 두 방식 중 하나로 통제된 접근을 제공한다.

### Option A. GitHub Private Repository Review

공식 심사자 계정을 비공개 저장소의 지정 협업자로 초청하여 검토권한을 부여하는 방식이다.

- 실명 또는 공식 계정이 확인된 심사자에게만 접근권한 부여
- 검토 목적에 필요한 최소 권한만 적용
- 심사기간에 한정해 접근을 유지하고 종료 후 초청 해제
- 초청·변경·해제 이력을 별도로 기록
- 원자료 접근권한과 코드 접근권한을 분리
- 코드 재배포, 공개 전환 또는 제3자 전달은 별도 승인 없이 허용하지 않음

비공개 저장소 초청은 검토 편의를 위한 접근통제 방식이며, 원자료 전체의 공개나 재배포 권한을 의미하지 않는다.

### Option B. Path-Abstracted Portable Reproducibility Package

공식 심사 범위에 맞춰 내부 인프라 정보를 제거한 별도 재현 패키지를 제공하는 방식이다.

포터블 패키지는 다음 원칙으로 구성한다.

- 절대 마운트 경로를 상대경로 또는 설정파일 기반 경로로 추상화
- 내부 URL, 계정 식별자, 상태 스냅샷과 비공개 메타데이터 제거
- 심사 대상 결과를 재검증하는 데 필요한 최소 코드만 포함
- 환경 명세, 실행순서, 입력·출력 스키마 및 제한사항 문서화
- 승인된 입력 스냅샷과 결과 산출물 사이의 manifest 제공
- SHA-256 체크섬으로 패키지 무결성 확인
- 공개 원자료가 없는 항목은 실행 가능 범위와 불가능 범위를 명시

이 패키지는 내부 운영환경 전체를 복제하는 배포본이 아니다. 목적은 승인된 결과의 제한적 재검증이며, 비공개 인프라 토폴로지와 전체 오케스트레이션 제어면은 포함하지 않는다.

> **Access Principle**  
> 코드 접근은 일반 공개가 아니라 공식 심사와 기술감사를 위한 제한적 검토절차로 운영한다. 공개성의 범위를 확대하는 대신, 접근주체·검토목적·제공자산·유효기간을 명확히 하여 보안성과 검증가능성을 함께 유지한다.
